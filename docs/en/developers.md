# Developers

## Architecture

A static application, with no dependency and no build step. The scripts are loaded in this order by `index.html` and share the global objects `P` (engine) and `App` (interface).

| File | Role |
|---|---|
| `js/i18n.js` | interface language (`P.lang`: `?lang=en`, then the remembered choice, then the browser language), `P.t()` translation of French strings, `P.translateDom()` |
| `js/i18n-en.js` | English dictionary of the interface (`P.I18N.en`) |
| `js/model.js` | families (`P.FAMS`), French-law **catalogue**, type aliases, **relations** (`P.RELS`, `P.defaultRel`), state, **laws** (`P.registerJuris`, `P.setJuris`, `P.jurisOf`), **checking engine** (`P.analyze`): context of conditions, case files, incompatibilities, breached obligations, calculations (`check` functions of the catalogue), verdicts; automatic layout (`P.layout`) |
| `js/catalog-fr-en.js` | English translation of the French catalogue's texts (`P.JURIS.fr.en`) and English aliases of the French types |
| `js/catalog-uk.js` | catalogue of English law, England & Wales (`juris 'uk'`): types, conditions, incompatibilities, `check` functions (qualifying period, notice, redundancy pay, awards, minimum wage), annual figures as defaults (`DEF`), aliases and parameter aliases |
| `js/scenario.js` | tokenizer and **commands** (`P.runCommand`, French and English keywords), scenario parsing (`P.parseScenario`, front matter `droit:`), `P.buildState`, studio export (`P.toCommands`), mini markdown renderer (`P.md`) |
| `js/docs.js` | built-in help, format specification (`P.FORMAT_DOC`, `P.FORMAT_DOC_EN`, whose catalogues are generated by `P.catalogDoc(jurisId, lang)`), AI prompts (`P.AI_PROMPT`, `P.AI_PROMPT_EN`, `P.IA_CONSIGNE`) |
| `js/library.js` · `js/library-en.js` · `js/library-uk.js` | built-in scenarios (`P.LIBRARY`): French law in French; the same in English (same ids, `lang: 'en'`); English law (`uk-*` ids, `lang: 'en'`, front matter `droit: uk`) |
| `js/app.js` | SVG canvas and animations, interactions, palette, inspector, cinema player, studio, modals, law and language selectors |
| `js/scorm.js` · `js/scorm-runtime.js` | SCORM export and dialogue with the platform inside a package |
| `css/app.css` | styles |

### Principles

- **The state** (`App.state`) is a JSON object: `entities`, `links`, `options` (`verif`, `droit`), `view`. Every change goes through `App.commit()`, which reruns the analysis and the rendering.
- **The analysis** (`P.analyze`) is fully recomputed at every change; it first activates the law of the state (`P.setJuris(st.options.droit)`).
- **Laws**: `P.registerJuris({ id, lang, names, label, labelEn, catalog, categories, aliases, paramAliases, currency, defaults })`. `P.setJuris(id)` builds the active catalogue in the interface language (with the translation `J[lang]` if there is one) and caches it per law and language. A new law is a new `catalog-xx.js` file loaded after `model.js`.
- **Adding a type**: an entry in the law's catalogue is enough (family, icon, label, description, `req`, `excl`, `ouvre`, `grp`, `params`, optional `check(a)`). The palette, the inspector, the documentation catalogue and the checks use it directly.
- **In cinema mode**, the state of step *n* is rebuilt by replaying the commands of steps 0 to *n* (`P.buildState`).

## Adding a built-in scenario

Add an object `{ id, lang: 'en', md }` to `P.LIBRARY` in `js/library-uk.js` (English law: start `md` with the front matter `---\ndroit: uk\n---`) or `js/library-en.js` (French law in English, same id as the French one). In these files, command blocks are written `~~~scene` (not with backticks, which would close the JavaScript string), and the text must contain neither a backtick nor `${`.

Then check it:

```bash
node tools/build.js
node skill/scenario-contract-lab/scripts/verifier.js docs/en/scenarios/<id>.md
```

Add it to the table of `docs/en/scenarios.md` too.

## Synchronising the documentation and the skill

`tools/build.js` regenerates, from the code:
- `docs/format-scenario.md` (`P.FORMAT_DOC`) and `docs/en/format-scenario.md` (`P.FORMAT_DOC_EN`);
- `docs/scenarios/*.md` (French scenarios) and `docs/en/scenarios/*.md` (English scenarios: French law in English and English law);
- `docs/instructions-ia.md` and `docs/en/instructions-ia.md`, the pages to give to any AI: mission (text in `tools/build.js`) + format + checking rules + example (the French non-compete clause / the English restrictive covenants);
- the skill references (`format.md`, `format-en.md`, `regles-de-calcul.md` and `checking-rules-en.md` copied from `docs/`, `exemple.md`, `example-en.md`);
- the copy of the engine in `skill/scenario-contract-lab/scripts/lib/` (`i18n.js`, `i18n-en.js`, `model.js`, `catalog-fr-en.js`, `catalog-uk.js`, `scenario.js`).

Run it after any change to the engine, the catalogues, the format or the scenarios. Then, to rebuild the installable skill file (zip archive of the folder, `.skill` extension):

```bash
python tools/package_skill.py
```

## Every April

The English catalogue's annual figures are in `DEF` at the top of `js/catalog-uk.js` (`week_cap`, `comp_cap`, `nmw21`, `nmw18`, `nmw16`) and repeated in the descriptions of the types concerned and in `docs/en/checking-rules.md`. When the Employment Rights Act 2025 reforms come into force (qualifying period, compensatory award cap…), update `qualifying_years`, the `check` functions and the `REFORM` texts, then rerun `node tools/build.js`.

## Screenshots

`tools/screenshots.js` produces `docs/images/*.jpg` (French interface), `docs/images/en/*.jpg` (English interface, English law) and the `contract-lab*.png` images at the root (`ONLY=en/ node tools/screenshots.js` redoes only the English ones), driving Microsoft Edge or Chrome headless:

```bash
node tools/screenshots.js
```

## Documentation

This site uses [Docsify](https://docsify.js.org) 4.13.1, loaded from a CDN: each page is a plain `.md` file of `docs/` (French) or `docs/en/` (English), and the sidebars are `docs/_sidebar.md` and `docs/en/_sidebar.md` (Docsify loads the nearest one). The `.nojekyll` file at the root is essential: without it, GitHub Pages ignores files starting with `_`, and the sidebar disappears. The "Prepare your course with an AI" box is HTML inside the markdown; its buttons are handled by the script of `docs/index.html` (the `data-path` attribute of `.js-ia-url` gives the instructions page). The `llms.txt` file at the root guides AIs exploring the site. The pages `regles-de-calcul.md` and `en/checking-rules.md` are also references for the skill: keep them accurate.
